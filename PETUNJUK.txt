NAMETAGFLOW V13.2 · JOHN STORE
Pindah tahap massal, simpan berkelompok, dan visual 10 model

PAKET INI SIAP DIPASANG. Belum diterapkan ke website atau Apps Script aktif.

YANG BERUBAH
1. Centang beberapa pesanan, pilih tahap tujuan 1–7, lalu klik Pindahkan.
   Bisa langsung dari Cetak vinyl ke Pengiriman, termasuk pilihan lintas halaman.
2. Pengiriman simpan berkelompok, maksimal 10 perubahan per permintaan.
   Draf yang belum pernah dikirim dapat digabung jika pesanan yang sama diubah lagi.
   Setiap pesanan tetap harus dikonfirmasi pusat sebelum keluar dari antrean simpan.
3. Gambar contoh Model 1–10 tampil langsung di tabel. Klik gambar untuk memperbesar.
   Contoh juga tampil di formulir dan mengikuti model yang dipilih.
   Gambar berasal dari katalog asli John Store. Nama/logo contoh bukan hasil cetak pesanan.

PASANG BAGIAN A: APPS SCRIPT
Perubahan kecepatan simpan memerlukan Code.gs baru, bukan hanya file website.

1. Buka proyek Apps Script yang sekarang digunakan NametagFlow.
   Gunakan proyek yang sama, dengan deployment /exec yang saat ini dipakai website.
2. Buka file Code.gs. Ganti seluruh isinya dengan isi backend/Code.gs dari ZIP ini.
   Simpan perubahan.
3. Buka Deploy / Terapkan > Manage deployments / Kelola deployment.
4. Pilih deployment web app yang aktif, klik ikon pensil / Edit.
5. Pilih New version / Versi baru, lalu Deploy / Terapkan.
   Mengedit deployment yang sama mempertahankan URL /exec yang sudah dipakai.
6. File backend/appsscript.json disertakan sebagai acuan konfigurasi yang sama:
   Asia/Jakarta, V8, executeAs USER_DEPLOYING, access ANYONE_ANONYMOUS.
   Jika konfigurasi aktif sudah sama, biarkan manifest yang sudah ada.

Tidak perlu menjalankan setupNametagFlow atau rotateAccessCodes untuk pembaruan ini.
Pertahankan kode akses, Script Properties, semua tab produksi, arsip, dan jurnal.
Paket ini tidak memerlukan migrasi atau pengosongan data.

PASANG BAGIAN B: WEBSITE GITHUB
1. Buka repositori adminzvck/nametagflow.html, cabang main.
2. Unggah dan ganti EMPAT file di folder utama yang sekarang dipakai:
   index.html
   styles.css
   core.js
   app.js
3. Commit perubahan, tunggu penerbitan GitHub Pages selesai.
4. Buka https://adminzvck.github.io/nametagflow.html/ lalu tekan Ctrl+Shift+R.
5. Pastikan tulisan versi di sidebar menjadi V13.2. Masuk seperti biasa.

Gunakan keempat file dari paket yang sama. Nama file harus core.js, bukan core(1).js.
Folder backend tidak perlu diunggah sebagai bagian pemasangan website.
Gunakan browser dan profil yang sama agar draf lokal tetap dapat dilanjutkan.
Jangan bersihkan data situs saat masih ada perubahan yang menunggu simpan.

CARA PINDAH BANYAK PESANAN LANGSUNG KE TAHAP 7
1. Atur pencarian, tanggal, atau filter tahap sesuai pesanan yang ingin dipindah.
2. Centang pesanan. Checkbox pada kepala tabel memilih halaman tersebut, maksimal 25.
3. Untuk seluruh halaman yang cocok, klik Pilih semua [jumlah] hasil filter.
4. Pada Pindah langsung ke, pilih 7 · Pengiriman.
5. Klik Pindahkan, periksa jumlah pesanan pada konfirmasi, lalu setujui.

Pesanan yang sudah berada di tahap tujuan dilewati. Perpindahan langsung hanya
mengubah tahap; nama, NIP, catatan, jumlah cetak, dan penanda cacat dipertahankan.
Tahap 7 tidak otomatis mengarsipkan pesanan. Arsipkan tahap 7 tetap tersedia terpisah.
Pesanan dengan konflik atau pemindahan arsip yang tertunda perlu diselesaikan dahulu.
Tombol Lanjut 1 tahap tetap tersedia untuk alur bertahap yang lama.

ANTREAN SIMPAN
Tampilan dan jumlah tahap berubah setelah draf tersimpan di perangkat. Label
Menunggu simpan tetap muncul sampai pusat mengonfirmasi. Pekerjaan dapat dilanjutkan.
Jika koneksi putus atau balasan hilang, pengiriman ulang memakai ID perubahan yang sama.
Konflik data ditahan untuk diperiksa, bukan menimpa perubahan operator lain.
Jika backend lama belum diperbarui, website tetap memakai pengiriman satu per satu.

VERIFIKASI
68 pengujian simulasi lulus: pindah langsung, lintas halaman, filter, draf offline,
balasan hilang, retry tanpa duplikat, konflik, arsip, autentikasi, backend lama,
impor massal, dan pemetaan visual Model 1–10. Sintaks dan ID kontrol HTML diperiksa.

Pada simulasi 25 perubahan berbeda: 3 permintaan simpan (10 + 10 + 5), sebelumnya 25.
Pada simulasi backend untuk 10 perubahan tahap: pembacaan rentang 60 menjadi 31;
pemformatan rentang teks 120 menjadi 10. Penulisan jurnal tetap dipertahankan.
Angka ini adalah jumlah panggilan, bukan jaminan waktu selesai pada koneksi nyata.
Backend bisa memecah kelompok lebih kecil bila pemrosesan sedang lambat.

Belum diuji secara visual di browser atau dengan transaksi produksi langsung.
Data pesanan aktif tidak digunakan untuk percobaan mutasi.
